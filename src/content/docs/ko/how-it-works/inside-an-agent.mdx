Agent는 고정된 Agent Product 버전으로 설정됩니다. 그 중심에는 **builder**가 있습니다. 생각하고, 도구로 행동하고, 결과를 확인하는 AI 루프입니다. 그 주위에는 builder가 읽는 것, 추론에 쓰는 모델, 호출할 수 있는 것이 있습니다. builder가 만들어 내는 것은 App입니다.

## builder

builder는 Agent의 격리된 샌드박스 안에서 일합니다. 각 턴에서 모델로 생각하고, 도구로 행동하고, 결과를 살피기를 일이 끝날 때까지 반복합니다. 그런 다음 코드를 플랫폼에 돌려줍니다.

## 컨텍스트와 메모리

| 구성 요소 | 내용 |
|---|---|
| 지시문 | `AGENTS.md`. 기본 규칙, 제품의 규칙, 플랫폼 기능, App 목록으로 턴마다 다시 작성됩니다. |
| 세션 | 대화 턴은 이전 세션을 이어 갑니다. 세션이 너무 커지면 새 세션이 시작됩니다. |
| 계획 파일 | `PLAN.md`와 `.steps` 파일이 계획과 체크박스를 다음 턴으로 이어 줍니다. |

숨겨진 메모장은 없습니다. 장기 메모리는 코드 자체와 이 파일들입니다.

## 모델

모든 모델 호출은 플랫폼의 모델 라우터를 거치며, 라우터가 작업마다 등급을 고릅니다. builder는 **GPT-6**, **Opus**, **DeepSeek** 같은 프런티어 모델로 일합니다. 업스트림 모델 키는 샌드박스에 절대 들어가지 않습니다.

## Skills

Skills는 글로 적어 둔 노하우입니다. builder는 작업에 필요할 때만 Skill을 읽습니다. 기본 세트와 제품 자체의 Skills는 턴마다 미러링됩니다.

| Skill | 도움 되는 일 |
|---|---|
| AI·이미지 | App에서 AI 호출, 이미지 생성 |
| AI 영상 | 영상과 음악 생성 |
| HyperFrames | HTML로 영상 만들기 |
| 데이터 | App 데이터베이스, 그리고 프런트엔드와 백엔드가 여기에 접근하는 방법 |
| 컨트랙트 | 컨트랙트 작성과 배포 준비 |
| 지갑·결제 | 지갑 로그인과 SSU 결제 |
| 이메일·예약 | 이메일 발송과 예약 작업 실행 |
| Lark 문서 | Lark 문서 읽기와 쓰기 |
| 브라우저 사용 | 페이지를 클릭해 보고 스크린샷 찍기 |
| UI 디자인 | 레이아웃과 시각적 감각 |
| React | React 모범 사례 |
| 디자인 | 디자인 시스템과 버전 업그레이드 |

## MCP

MCP 서버는 builder에게 외부 시스템을 다루는 읽기 전용 도구를 줍니다. 플랫폼이 builder 대신 호출하므로 계정 토큰은 샌드박스에 절대 들어가지 않습니다.

| MCP | 용도 |
|---|---|
| Pencil | 디자인 파일 읽기 |
| Figma | 디자인을 UI로 옮기기 |
| Playwright | 실제 브라우저에서 미리보기 테스트 |
| Context7 | 최신 라이브러리 문서 |
| GitHub | 저장소와 이슈 |
| Linear | 티켓과 요구 사항 |
| Notion | 문서와 데이터베이스 |
| Connectors | 연결된 Google Drive, Lark, Slack 계정 |
| 추가 MCP | Agent 소유자가 추가하는 서버 |

## 기본 제공 도구

| 도구 | 하는 일 |
|---|---|
| 읽기 · 찾기 | 파일을 읽고 코드를 검색 |
| 웹 가져오기 | 문서와 참고 사이트 읽기 |
| 할 일 목록 | 턴을 단계로 나누고 하나씩 체크 |
| 사람에게 묻기 | 제품 결정이 필요하면 멈추고 묻기 |
| 파일 편집 | 코드 작성과 수정 |
| 명령 실행 | 의존성 설치, 테스트 실행, 컴파일 |

## 만드는 것: App

Agent에는 App이 하나 이상 있습니다. App마다 다음을 따로 가집니다.

- **프런트엔드** — React, 정적 파일로 제공됩니다.
- **백엔드** — 첫 요청이 오면 시작되는 온디맨드 컨테이너.
- **데이터베이스** — 개발과 라이브는 분리됩니다. Publish는 항상 데이터를 유지합니다.
- **컨트랙트** — Base 위에 있으며 Agent 소유자가 배포합니다.
- **코드와 미리보기** — builder가 샌드박스에서 코드를 고치고 미리보기에서 실행합니다.

## 누가 점검하나

- **오케스트레이션.** 큰 요청은 계획이 됩니다. 사람이 승인하면 플랫폼이 작업 단위로 하나씩 보냅니다.
- **검토자.** 계획, 모든 작업, 전체 구축을 확인합니다. 통과하지 못한 작업은 수정으로 돌아갑니다. 처음 세 번의 수정은 세션을 이어 가고, 그 뒤로는 더 강한 모델로 새로 시작합니다.
- **가드레일.** Brainstorm은 읽기 전용입니다. 샌드박스는 `.env` 파일을 읽거나 작업 공간 밖으로 나갈 수 없습니다. 키와 커밋은 플랫폼에 남습니다.

## 세 가지 이야기

인터랙티브 다이어그램의 **Guided views**에서 다음 이야기를 재생합니다.

- **꽃집: 한 문장에서 결제되는 App까지.** "고객이 SSU로 결제하고 쿠폰을 받는 꽃집을 만들어 주세요." builder는 지시문과 계획을 읽고, 모델로 추론하고, 지갑·결제, 데이터, 컨트랙트 Skills를 읽은 뒤 파일을 편집하고 명령을 실행해 프런트엔드, 백엔드, 데이터베이스, 쿠폰 컨트랙트를 내놓습니다.
- **디자인으로 페이지 만들기.** "Figma 파일과 Linear 티켓대로 홈페이지를 만들어 주세요." builder는 MCP로 디자인과 티켓을 읽고, UI 디자인과 디자인 Skills를 따르며, 파일을 편집하고 Playwright로 미리보기를 확인합니다.
- **제품 소개 영상 추가.** "홈페이지에 30초짜리 소개 영상을 넣어 주세요." builder는 HyperFrames, AI 영상, AI·이미지 Skills를 읽고 영상을 렌더링해 프런트엔드에 넣습니다.

OpenStep은 한 문장을 동작하는 풀스택 App으로 바꿉니다. 이 페이지는 주요 구성 요소와 요청이 그 사이를 어떻게 지나가는지 보여 줍니다. 다음 페이지 [Agent 내부](/ko/how-it-works/inside-an-agent/)에서는 Agent 자체를 열어 봅니다.

## 구성 요소

| 구성 요소 | 하는 일 |
|---|---|
| 사용자와 방문자 | Agent와 채팅하며 만드는 사람, 수업을 운영하는 강사, 게시된 App을 쓰는 학습자. |
| 엣지 | 모든 요청을 HTTPS로 받아 도메인에 따라 builder 사이트나 게시된 App으로 보냅니다. |
| 플랫폼 서비스 | 웹 UI와 API: 로그인, Agent, 대화, Publish, 코스 페이지. |
| 플랫폼 데이터베이스 | PostgreSQL. Agent, 대화, 모든 턴과 모든 구축 실행을 저장합니다. |
| Agent 프레임워크 | Product → Agent → App. 고정된 Product 버전이 규칙, 방법론, Skills를 정하고, 그 버전으로 만든 Agent는 대화와 계획을 맡는 제어 영역 하나와 App 하나 이상을 가집니다. |
| 구축 오케스트레이션 | 큰 요청을 계획으로 실행합니다: 계획, 사람의 승인, 이어서 작업마다 구축 · 검사 · 검토 · 수정, 마지막으로 최종 검토. |
| builder 샌드박스 | Agent마다 격리된 컨테이너 하나. 턴마다 코드를 빌려 받고 끝나면 돌려줍니다. 키도 git 기록도 갖지 않습니다. |
| 모델 게이트웨이 | 모든 모델 호출은 플랫폼을 거치며, 플랫폼이 작업마다 모델 등급을 고릅니다 — GPT-6, Opus, DeepSeek 같은 프런티어 모델. |
| App 런타임 | 구축하는 동안은 미리보기, 게시하면 라이브. 프런트엔드는 정적 파일로 제공되고, 백엔드는 필요할 때 켜지는 컨테이너에서 실행됩니다. |
| App 데이터베이스 | App마다 자기 데이터를 가지며, 개발과 라이브는 분리됩니다. Publish는 항상 데이터를 유지합니다. |
| 기능 게이트웨이 | 실행 중인 App이 플랫폼에 요청할 수 있는 것: AI, 이메일, 온체인 트랜잭션, 예약 작업. 사용량은 SSU로 청구됩니다. |
| 외부 서비스 | Base 체인, 연결된 SaaS 계정, MCP 서버 — 항상 플랫폼을 거쳐 접근합니다. |

## 세 가지 이야기

인터랙티브 다이어그램의 **Guided views**에서 각 이야기를 단계별로 재생합니다.

### 한 문장이 코드가 되기까지

1. 누군가 Agent에 한 문장을 입력합니다.
2. 플랫폼이 턴을 확인하고(권한, 잔액, 이미 진행 중인 구축이 없는지) 기록합니다.
3. Agent 프레임워크가 이번 턴의 지시문, Skills, MCP를 조립하고 코드를 builder 샌드박스에 빌려줍니다.
4. builder가 모델 게이트웨이를 통해 모델을 호출하고, 코드를 고치고, 미리보기를 확인합니다.
5. 턴이 끝나면 코드가 플랫폼으로 돌아가고, 플랫폼이 이를 커밋합니다.

### 학습자: 코스 수강하기

1. 강사가 참여 링크를 공유합니다. 학습자는 지갑으로 로그인해 참여합니다.
2. 코스 페이지에 라이브 App이 들어 있습니다. 학습자는 아무것도 구축하지 않습니다.
3. 학습자가 하는 모든 일은 수업이 함께 쓰는 App 데이터에 기록됩니다.
4. 온체인 작업은 App 백엔드가 기능 게이트웨이를 통해 보내고, 수수료는 강사에게 청구됩니다.

### 강사: 수업 운영하기

1. 강사는 코스 제품으로 Agent를 만들어 수업을 엽니다.
2. 코스 변경 사항은 실제 데이터 위에서 동작하는 후보로 구축되고, 협업자가 검토한 뒤 라이브로 나갑니다.
3. 강사는 참여 링크를 공유하고 누가 참여했는지 확인합니다.
4. 새 학기는 **Start a new session**으로 시작합니다. 업무 데이터와 진행 상황은 처음부터 다시 시작하고, 멤버는 그대로 남습니다.

## 설계 원칙

- **모든 Agent에 하나의 구조.** 사용자가 시작할 수 있는 모든 경험은 Agent Product입니다. 작성자가 규칙, 방법론, Skills를 버전으로 고정하고, 플랫폼이 턴마다 이를 조립해 builder에게 줍니다.
- **두 단계의 제어.** 한 문장은 모델 도구 루프 한 번입니다. 큰 요청은 플랫폼이 단계별로 스케줄하는 계획입니다. Agent의 모든 App은 함께 라이브로 나가며, Publish는 데이터를 절대 지우지 않습니다.
- **확고한 보안 경계.** 샌드박스는 코드를 빌려 받을 뿐입니다. 키, git 커밋, 업스트림 모델 키는 플랫폼에 남고, 외부 계정 토큰은 플랫폼을 통해서만 쓰입니다.

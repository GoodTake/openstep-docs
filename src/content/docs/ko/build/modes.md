보내는 모든 메시지는 두 모드 중 하나로 실행됩니다. **Build**는 사이트를 바로 바꿉니다. **Brainstorm**은 먼저 질문하고 계획을 만듭니다. 모드는 **New agent**의 **Build** / **Brainstorm** 토글로 고르고, 이후에는 채팅 상자의 칩으로 바꿉니다.

1. 채팅 상자 아래쪽의 칩을 클릭합니다. 칩에는 모델과 모드가 표시됩니다(예: **Auto · Build**).
2. **Run mode**(**Choose how the agent works**) 아래에서 **Build**(**Changes it directly.**) 또는 **Brainstorm**(**Asks, plans, then builds task by task.**)을 고릅니다.
3. 메시지를 보냅니다. 상자 안의 안내 문구는 모드에 따라 달라집니다. **Build**에서는 **Tell me what you want to build**, **Brainstorm**에서는 **Describe it — I'll ask a few questions first**가 나옵니다.

![열린 채팅 상자의 칩: Select model 아래에 Auto, 그 아래에 Choose model, 그다음 Run mode에 Build가 선택되어 있고 그 아래에 Brainstorm.](/images/build/modes-1.webp)

## Build

builder는 요청을 읽고, 사이트를 바꾸고, 작업을 확인한 뒤 무엇을 했는지 알려 줍니다. 첫 메시지라도 계획을 쓰거나 승인을 기다리지 않습니다. Agent의 모든 앱을 살펴보고 어떤 앱을 바꿀지 정합니다. 변경 사항은 Preview에 나타납니다. **Publish**하기 전까지 라이브 사이트는 그대로입니다.

원하는 것이 분명하고 변경이 작거나 명확할 때 **Build**를 사용합니다. 커피숍 같은 첫 작은 사이트, 새 페이지, 다른 제목, 다른 영업시간 등이 그렇습니다.

## Brainstorm

builder가 한 번 이상의 라운드로 질문합니다. 그런 다음 계획 초안을 만들고, 승인할 때까지 멈춥니다. 승인하면 계획을 작업별로 빌드하고, 각 작업을 확인한 뒤, 최종 검토로 마무리하여 **Publish**할 준비를 마칩니다. 질문은 [질문에 답하기](/ko/agent/answer-questions/)를, 계획은 [계획 승인하기](/ko/agent/approve-plan/)를 참고하세요.

아이디어가 아직 열려 있거나 계획이 필요할 만큼 사이트가 클 때 **Brainstorm**을 사용합니다. 예를 들어 주문도 받고 확인 이메일도 보내는 커피숍이 그렇습니다.

기존의 글, 이름, 숫자, 색, 이미지만 바꾸는 작은 수정에는 계획이 필요 없습니다. **Brainstorm**에서도 builder가 바로 처리합니다.

## 알아 두기

- 모드는 메시지 사이에 바꿀 수 있지만 builder가 작업하는 동안에는 바꿀 수 없습니다. 턴이 끝날 때까지 칩이 회색으로 비활성화됩니다.
- **Brainstorm** 빌드에는 자체 조작인 **Pause**와 **Stop**, 그리고 자체 진행 표시가 있습니다. [진행 상황 확인하기](/ko/build/progress/)를 참고하세요.
- **Build**로 시작했다가 변경이 생각보다 크다고 드러나면 나중에 **Brainstorm**으로 바꿀 수 있습니다.

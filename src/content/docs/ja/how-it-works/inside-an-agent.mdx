Agent は、凍結された Agent Product の版によって設定されます。中心にあるのは **builder** です。考え、ツールで行動し、結果を確かめる AI のループです。その周りに、builder が読むもの、推論に使うモデル、呼び出せるものがあります。builder が生み出すのが App です。

## builder

builder は Agent の隔離されたサンドボックスの中で動きます。各ターンでモデルを使って考え、ツールで行動し、何が起きたかを確かめる。これを仕事が終わるまで繰り返します。終わったらコードをプラットフォームに返します。

## コンテキストとメモリ

| 要素 | 内容 |
|---|---|
| 指示 | `AGENTS.md`。基本ルール、Product のルール、プラットフォームの機能、App の一覧から毎ターン書き直される。 |
| セッション | 会話のターンは前のセッションを再開する。セッションが大きくなりすぎると、新しいセッションが始まる。 |
| 計画ファイル | `PLAN.md` と `.steps` ファイルが、計画とそのチェックボックスをターンからターンへ引き継ぐ。 |

隠れたノートはありません。長期的な記憶は、コードそのものとこれらのファイルです。

## モデル

すべてのモデル呼び出しはプラットフォームのモデルルーターを通り、タスクごとに階層が選ばれます。builder は **GPT-6**、**Opus**、**DeepSeek** などの最先端モデルで作業します。上流のモデルキーがサンドボックスに入ることはありません。

## Skills

Skills は文章にまとめたノウハウです。builder はタスクに必要なときだけ読みます。基本セットと Product 独自の Skills が、毎ターンミラーされます。

| Skill | 役立つこと |
|---|---|
| AI と画像 | App から AI を呼ぶ、画像を生成する |
| AI 動画 | 動画と音楽を生成する |
| HyperFrames | HTML から動画を作る |
| データ | App のデータベースと、フロントエンドとバックエンドからのつなぎ方 |
| コントラクト | コントラクトを書き、デプロイの準備をする |
| ウォレットと決済 | ウォレットでのサインインと SSU 決済 |
| メールと定期実行 | メールの送信とスケジュールタスクの実行 |
| Lark 文書 | Lark ドキュメントの読み書き |
| ブラウザ操作 | ページをクリックして回り、スクリーンショットを撮る |
| UI デザイン | レイアウトと見た目のセンス |
| React | React のベストプラクティス |
| デザイン | デザインシステムとバージョンアップ |

## MCP

MCP サーバーは、外部システムに対する読み取り専用のツールを builder に与えます。プラットフォームが builder に代わってそれらを呼ぶため、アカウントのトークンがサンドボックスに入ることはありません。

| MCP | 用途 |
|---|---|
| Pencil | デザインファイルを読む |
| Figma | デザインを UI にする |
| Playwright | 実際のブラウザでプレビューをテストする |
| Context7 | 最新のライブラリドキュメント |
| GitHub | リポジトリと issue |
| Linear | チケットと要件 |
| Notion | ドキュメントとデータベース |
| Connectors | 接続した Google Drive、Lark、Slack のアカウント |
| その他の MCP | Agent のオーナーが追加するサーバー |

## 組み込みツール

| ツール | すること |
|---|---|
| 読む・探す | ファイルを読み、コードを検索する |
| Web 取得 | ドキュメントや参考サイトを読む |
| ToDo リスト | ターンをステップに分け、一つずつチェックする |
| 人に聞く | プロダクト上の判断が必要なとき、止まって質問する |
| ファイル編集 | コードを書き、変更する |
| コマンド実行 | 依存関係のインストール、テストの実行、コンパイル |

## 作るもの: App

Agent は一つ以上の App を持ちます。各 App はそれぞれ次のものを持ちます。

- **フロントエンド** — React。静的ファイルとして配信される。
- **バックエンド** — 最初のリクエストで起動する、オンデマンドのコンテナ。
- **データベース** — 開発用と本番用は分かれている。Publish は常にデータを残す。
- **コントラクト** — Base 上にあり、Agent のオーナーがデプロイする。
- **コードとプレビュー** — builder がサンドボックスでコードを編集し、プレビューで動かす。

## 誰がチェックするか

- **オーケストレーター。** 大きな依頼は計画になります。人が承認すると、プラットフォームがタスクごとに振り分けます。
- **レビュアー。** 計画、各タスク、構築全体をチェックします。不合格の作業は修正に戻されます。最初の 3 回の修正ラウンドはセッションを再開し、それ以降はより強いモデルで新しく始めます。
- **ガードレール。** Brainstorm は読み取り専用です。サンドボックスは `.env` ファイルを読めず、作業領域の外にも出られません。キーとコミットはプラットフォームに残ります。

## 三つのストーリー

インタラクティブな図の **Guided views** で、次のストーリーを再生できます。

- **花屋: 一文から決済できる App へ。** 「お客さんが SSU で支払い、クーポンをもらえる花屋を作って。」builder は指示と計画を読み、モデルで推論し、ウォレットと決済、データ、コントラクトの Skills を読み、ファイルを編集してコマンドを実行します。そしてフロントエンド、バックエンド、データベース、クーポンのコントラクトを届けます。
- **デザインからページを作る。** 「Figma のファイルと Linear のチケットからホームページを作って。」builder は MCP を通じてデザインとチケットを読み、UI デザインとデザインの Skills に従い、ファイルを編集して Playwright でプレビューを確認します。
- **製品紹介動画を追加する。** 「ホームページに 30 秒の紹介動画を追加して。」builder は HyperFrames、AI 動画、AI と画像の Skills を読み、動画をレンダリングしてフロントエンドに追加します。

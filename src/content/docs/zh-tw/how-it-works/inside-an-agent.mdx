Agent 由一個凍結的 Agent Product 版本設定而成。它的核心是 **builder**：一個會思考、用工具行動、再檢查結果的 AI 迴圈。圍繞著它的，是它讀取的內容、用來推理的模型，以及它能呼叫的東西。它產出的就是 App。

## builder

builder 在 Agent 的隔離沙箱裡工作。每一輪它用模型思考、用工具行動、查看結果，反覆進行直到工作完成，接著把程式碼交還給平台。

## 上下文與記憶

| 部分 | 內容 |
|---|---|
| 指令 | `AGENTS.md`，每一輪都根據基礎規則、產品規則、平台能力與 App 清單重新寫成。 |
| 工作階段 | 一輪對話會延續上一個工作階段。工作階段變得太大時，就換一個新的。 |
| 計畫檔 | `PLAN.md` 與 `.steps` 檔案把計畫和勾選框從一輪帶到下一輪。 |

沒有隱藏的筆記本：長期記憶就是程式碼本身加上這些檔案。

## 模型

每一次模型呼叫都經過平台的模型路由，由它為每個任務挑選層級。builder 搭配前沿模型工作，例如 **GPT-6**、**Opus** 與 **DeepSeek**。上游模型金鑰從不進入沙箱。

## Skills

Skills 是寫下來的專業知識。builder 只在任務需要時才讀取對應的 Skill。基礎 Skills 與產品自己的 Skills 每一輪都會同步進來。

| Skill | 協助的事 |
|---|---|
| AI 與圖片 | 在 App 裡呼叫 AI、生成圖片 |
| AI 影片 | 生成影片與音樂 |
| HyperFrames | 用 HTML 製作影片 |
| 資料 | App 的資料庫，以及前端與後端如何存取它 |
| 合約 | 撰寫合約並準備部署 |
| 錢包與付款 | 錢包登入與 SSU 付款 |
| 郵件與排程 | 寄送電子郵件與執行排程任務 |
| Lark 文件 | 讀寫 Lark 文件 |
| 瀏覽器操作 | 點擊瀏覽頁面並截圖 |
| UI 設計 | 版面與視覺品味 |
| React | React 最佳實務 |
| 設計 | 設計系統與版本升級 |

## MCP

MCP 伺服器讓 builder 能以唯讀工具存取外部系統。平台代替 builder 呼叫它們，所以帳號權杖從不進入沙箱。

| MCP | 用途 |
|---|---|
| Pencil | 讀取設計稿 |
| Figma | 把設計轉成 UI |
| Playwright | 在真實瀏覽器裡測試預覽 |
| Context7 | 最新的函式庫文件 |
| GitHub | 儲存庫與 issue |
| Linear | 工單與需求 |
| Notion | 文件與資料庫 |
| Connectors | 已連結的 Google Drive、Lark 與 Slack 帳號 |
| 更多 MCP | Agent 擁有者加入的伺服器 |

## 內建工具

| 工具 | 作用 |
|---|---|
| 讀取 · 搜尋 | 讀取檔案、搜尋程式碼 |
| 抓取網頁 | 閱讀文件與參考網站 |
| 待辦清單 | 把一輪拆成步驟並逐項勾選 |
| 向人提問 | 需要產品決定時停下來詢問 |
| 編輯檔案 | 撰寫與修改程式碼 |
| 執行指令 | 安裝相依套件、執行測試、編譯 |

## 它建造的東西：App

一個 Agent 有一個或多個 App。每個 App 都有自己的：

- **前端**——React，以靜態檔案提供。
- **後端**——隨需容器，收到第一個請求時才啟動。
- **資料庫**——開發與線上分開存放。Publish 一律保留資料。
- **合約**——在 Base 上，由 Agent 擁有者部署。
- **程式碼與預覽**——builder 在沙箱裡編輯程式碼，並在預覽中執行。

## 誰負責把關

- **編排。** 大型需求會變成一份計畫。由人核准後，平台再逐個任務派發。
- **審查者。** 審查者檢查計畫、每一個任務以及整體建造。沒通過的工作會退回修正：前三輪修正延續原本的工作階段，之後的修正改用更強的模型重新開始。
- **防護機制。** Brainstorm 是唯讀的。沙箱讀不到 `.env` 檔案，也無法離開自己的工作區。金鑰與提交都留在平台。

## 三個故事

互動式架構圖會在 **Guided views** 下播放這些故事：

- **花店：一句話做出能收款的 App。**「做一間花店，顧客用 SSU 付款，還能領優惠券。」builder 讀取指令與計畫，透過模型推理，讀取錢包與付款、資料、合約三項 Skills，編輯檔案、執行指令，交付前端、後端、資料庫與優惠券合約。
- **照設計稿做頁面。**「照 Figma 檔和 Linear 工單做首頁。」builder 透過 MCP 讀取設計稿與工單，依循 UI 設計與設計兩項 Skills，編輯檔案並用 Playwright 檢查預覽。
- **加上產品影片。**「在首頁加一支 30 秒的介紹影片。」builder 讀取 HyperFrames、AI 影片、AI 與圖片三項 Skills，產生影片並放進前端。

## 組成部分

| 部分 | 作用 |
|---|---|
| 使用者與訪客 | 與 Agent 對話來建造東西的建造者、開班授課的講師，以及使用已發布 App 的學員。 |
| 邊緣入口 | 以 HTTPS 接收每一個請求，並依網域分流：builder 網站或已發布的 App。 |
| 平台服務 | 網頁介面與 API：登入、Agent、對話、Publish 與課程頁。 |
| 平台資料庫 | PostgreSQL。存放 Agent、對話、每一個輪次與每一次建造執行。 |
| Agent 框架 | Product → Agent → App。凍結的 Product 版本固定了規則、方法與 Skills；據此建立的 Agent 有一個控制面（負責對話與計畫），以及一個或多個 App。 |
| 建造編排 | 把大型需求當成計畫來執行：先規劃、由人核准，再對每個任務進行建造 · 檢查 · 審查 · 修正，最後做一次最終審查。 |
| builder 沙箱 | 每個 Agent 一個隔離容器。每一輪借用程式碼，結束時交還。裡面不放任何金鑰，也沒有 git 歷史。 |
| 模型閘道 | 每一次模型呼叫都經過平台，由平台依任務挑選模型層級——例如 GPT-6、Opus 與 DeepSeek 等前沿模型。 |
| App 執行環境 | 建造時是預覽，發布後就是線上版。前端以靜態檔案提供；後端在隨需啟動的容器中執行。 |
| App 資料庫 | 每個 App 都有自己的資料，開發與線上分開存放。Publish 一律保留資料。 |
| 平台能力閘道 | 執行中的 App 可以向平台要求的能力：AI、電子郵件、鏈上交易與排程任務。用量以 SSU 計費。 |
| 外部服務 | Base 鏈、已連結的 SaaS 帳號與 MCP 伺服器——一律經由平台存取。 |

## 三個故事

互動式架構圖會在 **Guided views** 下逐步播放每一個故事。

### 一句話如何變成程式碼

1. 有人在 Agent 上輸入一句話。
2. 平台檢查這一輪（權限、餘額、沒有正在進行的建造），並把它記錄下來。
3. Agent 框架為這一輪組裝指令、Skills 與 MCP，並把程式碼借給 builder 沙箱。
4. builder 透過模型閘道呼叫模型、修改程式碼並檢查預覽。
5. 這一輪結束時，程式碼交還給平台，由平台提交。

### 學員：來上一門課

1. 講師分享加入連結。學員用錢包登入並加入。
2. 課程頁內嵌已上線的 App。學員不需要建造任何東西。
3. 學員所做的一切都寫進全班共用的 App 資料。
4. 鏈上操作由 App 的後端透過平台能力閘道送出；費用記在講師帳上。

### 講師：開一個班

1. 講師從課程產品建立一個 Agent，開出一個班。
2. 課程的變更會建成一個在真實資料上執行的候選版本；協作者審查後才上線。
3. 講師分享加入連結，並查看誰已經加入。
4. 新學期用 **Start a new session** 開始：業務資料與進度重新開始，成員保留。

## 設計原則

- **每個 Agent 都是同一種結構。** 使用者能啟動的每一種體驗都是一個 Agent Product。作者把規則、方法與 Skills 凍結成一個版本；每一輪由平台為 builder 組裝它們。
- **兩層控制。** 一句話就是一次模型工具迴圈。大型需求是由平台逐步排程的計畫。一個 Agent 的所有 App 一起上線，Publish 從不刪除資料。
- **硬性的安全邊界。** 沙箱只拿到借出的程式碼。金鑰、git 提交與上游模型金鑰都留在平台，外部帳號的權杖也只透過平台使用。
